# Deck

Design a slide deck as a sequence of decisions for a busy reviewer. One slide has one conclusion, one visual job, and a visible evidence pointer.

## Build the narrative

`一句话价值 → 真实问题 → 调研发现 → 技术/产品 response → 关键指标 → 验证 → 用户/场景 → 竞品 → IP/壁垒 → 商业化 → 团队成长 → 社会价值 → 下一步`

Use a different spine for red-tour, industry, vocational, and sprout tracks. For industry projects, reserve a clear `命题匹配 → 对策讲解 → 实物/演示 → 专家问辩` chain.

## Slide QA

Check every page for: conclusion in the title, readable units, source/date, consistent numbers with the project book, student-owned work, and no unverified superlatives. Flag image-only pages as `visual review required`, not as empty.

## What to return

Provide a slide table (`no`, `purpose`, `headline`, `visual`, `evidence_ids`, `speaker cue`, `risk`) plus a cut list for time pressure. Page counts, timing, fonts, and effects are local rules until the 2026 official evaluation rules or a school/province notice says otherwise.

See `references/slide-patterns.md` for reusable patterns from national gold/silver examples.
