# Proposal

Treat the project book as an auditable argument, not a long brochure. Every section must advance one claim and point to evidence.

## Recommended spine

`项目概况 → 行业/政策背景 → 调研与痛点 → 科创历程 → 痛点—技术—指标 → 产品与场景 → 竞品 → IP/成果 → 验证与合作 → 团队/成长 → 商业模式 → 财务/风险 → 社会价值 → 规划`

Select only the sections required by the chosen track and maturity. This is a learned pattern from past materials, not a 2026 page-count rule.

## Audit each section

For each heading write: `section_claim`, `why_now`, `evidence_ids`, `quantified_result`, `student_contribution`, `bridge_to_next`. Mark unsupported content `TBD—owner—date`; never fill it with a plausible number.

## Rewrite pattern

Use `problem → user/context → intervention → measurable change → proof → limitation`. Replace adjectives such as “国际领先” with a comparison table whose baseline, test condition, sample size, and source are visible.

## Track lenses

- **高教创意/创业：** foreground learning, research depth, innovation, team contribution, and industry value.
- **红旅：** prove participation, field work, beneficiary change, sustainability, and the technical/business mechanism.
- **产业：** map every response to the enterprise question; include implementation, demonstrator, contract or acceptance evidence.
- **职教/萌芽：** prioritize craft, practice, autonomy, growth, and age/education eligibility.

## Deliverables

Return a section map, a claim–evidence ledger, five highest-risk gaps, and a revision queue before offering prose. A complete draft is allowed only for facts supplied and verified by the team.
