# GPS conclusion language

Attach exactly one status to every material conclusion. Status describes the support for the statement, not project quality.

| Status | Use only when |
| --- | --- |
| `verified` | An inspectable primary or authoritative source supports the exact statement, with the relevant locator and conditions. |
| `supported` | Inspectable evidence materially supports the statement, but an independent check, full condition set, or limitation remains open. |
| `conditional` | The statement holds only under named assumptions, test conditions, scope, or unresolved qualification. |
| `hypothesis` | The statement is a plausible opportunity or explanation that requires validation; it is not presented as a result. |
| `missing` | A required fact, linkage, source, or condition has not been supplied or cannot be inspected. |
| `contradicted` | Traceable sources materially conflict; preserve both sources and state what must be resolved. |

## Claim ceiling

- A path string, logo, patent, publication, intention, forecast, historical case, or file label alone does not make a claim `verified`.
- Quantitative superiority needs a linked source, baseline, metric, unit, condition or locator, and stated limitation before it can be stronger than `conditional`.
- Market size, customer value, price, order, revenue, margin, beneficiary change, adoption, and student ownership remain `hypothesis` or `missing` without their matching evidence.
- A historical rubric used for a 2026 project is `historical_baseline`, not an official 2026 score or requirement.

## Award language

Never predict, promise, imply, or label readiness as a national, provincial, gold, silver, bronze, finalist, winning, or award-level outcome. Report only evidence status, rubric alignment, GPS readiness state, known limitations, and next proof-building actions.
